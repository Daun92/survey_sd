## 2. 핵심 원리 — 결정 원장이 단일 진실원

- 정제 DB(엑셀)를 **직접 고치지 않습니다.** 모든 변경은 **결정(decision)** 으로 원장에 기록됩니다.
- 원장 = `config/decisions_21th.yaml`(현재 21회 시험용. 22회 본가동 시 `decisions_22th.yaml`).
- 산출물(김태웅 xlsx·chart_data)은 **raw + 결정**으로 매번 재생성되는 파생물입니다 → 누가·무엇을·왜가 100% 남고, 언제든 똑같이 재현됩니다.
- 결정 3유형 + 1검수기록:
  - `correction` — 값 보정(이상치)
  - `exclusion` — 응답자 포함/제외
  - `reclassification` — 업종 재분류
  - `outlier_review` — 이상치 승인/무시(데이터 불변, 검수 기록)

## 3. 화면별 사용법

상단 탭으로 이동합니다.

### 상태판 `/`
기업/공공 모집단 N, 정제 DB 행 수, 중복 조직 그룹. (검증 엔진 실시간 산출)

### 이상치 검토 `/outliers`
거시지표(매출·교육예산·인원수) 이상치 후보를 등급(critical/high/medium)·규칙별로 표시.
- **승인** — 값이 정상. 변경 없이 검수 완료 기록.
- **무시** — 대상 아님. 변경 없이 검수 완료 기록.
- **보정** — 보정값 입력 후 `보정` → `correction` 결정 추가(산출 시 반영).
- 상단 카드에 미결 건수가 실시간 갱신. severity·"미결만" 필터 제공.

### 업종 재분류 `/reclassify`
기업 모집단 중 업종이 `etc`(기업기타)인 응답자 목록. 자유응답(R_Cate_Name)을 보고 표준 업종(1~13)으로 매핑 → `reclassification` 결정.
- 주요업종 선정(재분류 후 카운트 ≥10)은 **산출/미리보기** 단계에서 수행.

### 포함/제외 `/exclude`
- 회사명 또는 resp_id로 검색 → 해당 응답자 **제외**.
- 하단 "현재 제외" 목록에서 **포함 복원** 가능.
- 상단 카드의 기업/공공 모집단 N이 토글 즉시 반영(`apply_decisions` + `build_population` 실시간 산출).

### 산출/미리보기 `/build`
- 상단: 결정 원장 건수·최종 갱신, 김태웅/chart_data 산출물의 생성시각·신선도(최신 / 재생성 필요 / 미상).
- **재생성** 버튼 → 결정을 정제 DB에 적용한 스냅샷으로 검증된 stage4 스크립트 2종을 실행 → 그 자리에 요약 표시:
  - 기업/공공 모집단 N, 도표 수, 집계법 분포
  - 김태웅 시트별 N 표
  - 적용 경고 / 실행 로그(접기)
- 산출 파일(직접 열어 검증 가능):
  - `4_aggregated/_app_김태웅.xlsx` (7시트 빈도·비율)
  - `4_aggregated/_app_chart_data.json` (도표 집계)
  - → `_app_` 접두 = 재생성 가능한 파생물(검증 fixture와 분리).

> 신선도가 "미상"으로 보이면, 원장에 갱신시각이 아직 없는 경우입니다. 화면에서 결정을 1건 저장하면 기록됩니다.

## 6. 알아둘 점

- 상태판(`/`)의 모집단 N은 현재 raw 기준이라, 제외 화면(`/exclude`)의 실시간 N과 결정 반영 여부가 다를 수 있습니다(상태판은 결정 미적용).
- 이상치 검토에서 컬럼 간(cross-column) 후보(예: `교육예산-매출` 식)에 보정을 누르면 대상 필드가 실제 컬럼이 아니므로, 이런 행은 승인/무시하거나 단일 컬럼 후보에서 보정하세요.
